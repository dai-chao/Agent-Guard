# 修复指南

## 推荐流程

1. **先扫描**：防封扫描 → 跑一轮完整检测  
2. **读详情**：确认路径、变量名、风险等级，勿盲目全选修复  
3. **再修复**：免费版按手动指引；Pro 勾选需要修复的项后一键执行  
4. **复扫**：确认合规灯与评分变化，留一次底  

## Pro 可自动修复的项目（示例）

| 类型 | 做什么 |
|------|--------|
| 时区校正 | 设置为推荐时区（如 `Asia/Taipei` 等，以应用内建议为准） |
| 关闭自动时区 | 避免 IP 漂移时时区跟随跳变 |
| 清除 Shell 代理 | 移除 `.zshrc` 等中的 proxy export |
| 清除工具链代理 | 清理 npm / pip 等代理残留 |
| 清理 Agent 配置 | 移除各产品配置中的 `proxy` / `base_url` |
| Claude 状态备份 | 高风险状态文件自动备份 |

无法自动修复的项会提供**手动操作指引**。

## 备份与回滚

- 自动修复前，原配置会备份到：`~/.agent-guard/backups/`
- 若修复后行为异常，可从该目录取回对应备份文件恢复
- 建议修复前自行再复制一份关键配置（如 `settings.json`、Shell rc）

## 注意事项

- 修复可能影响你正在使用的代理工作流；若你**有意**使用本地代理仅供终端，请区分「系统 / Agent 配置泄漏」与「个人网络需求」
- 清理 `base_url` / 第三方端点后，相关自定义 API 中转会失效，属预期行为
- 不要在未确认的情况下把扫描报告或完整配置发到公开论坛（可能含密钥）

更多边界见 [隐私与边界](Privacy)。
